 > Lightweight Kubernetes configuration sanity checks. Requires `kubectl` and `jq`; execution time depends on cluster size.

**What it checks:** with an authorized, working `kubectl` context, the script reports potentially privileged or root workloads, missing resource limits, and resources in the default namespace. It can export a Markdown report.

**Kube-Simple-Audit** is a small, read-only Bash audit helper. It flags common misconfigurations and writes a **Markdown report** you can paste into tickets or GitHub Step Summary.

## Getting started (review before running)

Use a Kubernetes context for a cluster you own or have explicit permission to inspect. Run the script with the least privilege that permits listing Pods.

Recommended: clone, read and run the script locally:

```bash
git clone https://github.com/ranas-mukminov/Kube-Simple-Audit.git
cd Kube-Simple-Audit
less audit.sh
bash audit.sh --markdown -o report.md
```

### Convenience one-liner

Only use this after reviewing the script and accepting the supply-chain risk of executing downloaded code. Requires `kubectl` and `jq`:

```bash
curl -fsSL https://raw.githubusercontent.com/ranas-mukminov/Kube-Simple-Audit/main/audit.sh | bash
```

Markdown report:

```bash
curl -fsSL https://raw.githubusercontent.com/ranas-mukminov/Kube-Simple-Audit/main/audit.sh | bash -s -- --markdown
# → kube-simple-audit-report.md
```

Or clone:

```bash
git clone https://github.com/ranas-mukminov/Kube-Simple-Audit.git
cd Kube-Simple-Audit
./audit.sh --markdown -o report.md
```

## Checks

| # | Check | Why it matters |
|---|--------|----------------|
| 1 | Privileged pods | Near-root on the node |
| 2 | Missing `runAsNonRoot` | Containers may run as UID 0 |
| 3 | Missing resource limits | Noisy-neighbor / DoS risk |
| 4 | Workloads in `default` | Weak tenancy / RBAC hygiene |

## Markdown report + Actions summary

- `--markdown` / `-o FILE` writes a structured MD report (summary table, samples, next steps, CTA).
- When `GITHUB_STEP_SUMMARY` is set (GitHub Actions), the same report is appended automatically — **no secrets required** beyond the runner's kubeconfig / your local kubeconfig.

Example job (copy into *your* workflow; needs cluster credentials you already manage):

```yaml
# examples only — do not enable without a kubeconfig secret you control
- name: Kube Simple Audit
  env:
    KUBECONFIG: ${{ secrets.KUBECONFIG }}
  run: |
    curl -fsSL https://raw.githubusercontent.com/ranas-mukminov/Kube-Simple-Audit/main/audit.sh | bash -s -- --markdown
    cat kube-simple-audit-report.md >> "$GITHUB_STEP_SUMMARY"
```

## Example report structure

The Markdown report generated by `audit.sh --markdown` has these sections (counts and findings vary by cluster; this is the structure, not a real cluster's findings):

- `# Kube-Simple-Audit Report`
- `## Summary` — a PASS/FAIL table per check: privileged pods, potential root containers, missing resource limits, default-namespace workloads
- `## Findings (samples)` — samples for each check above
- `## What to do next`

## Privacy and limitations

The script queries Kubernetes using your current kubeconfig and does not send the findings to an external service. **Do not use an administrative kubeconfig unless required.** Output reports can contain namespace, workload, and context names; redact them before sharing.

This is a small set of configuration checks, **not** a complete security assessment, penetration test, or CIS benchmark implementation. Review the findings in context.

# Security Policy

## Scope

This repository provides open-source reference code and documentation. It is **not** a certification, complete audit, or guarantee of secure production deployment. Review the limitations and test changes in an isolated environment before using them on real systems.

## Reporting a vulnerability

Please use GitHub's **Security → Report a vulnerability** private disclosure flow if it is available for this repository. If private reporting is unavailable, contact the maintainer using the channels linked from the [GitHub profile](https://github.com/ranas-mukminov). Do not post exploit details, credentials, private infrastructure addresses, customer information or sensitive proof of concept material in a public issue.

A useful report includes:
- affected file and version or commit;
- reproducible steps using **synthetic data and systems you control**;
- observed versus expected behavior;
- security impact, with no production data attached;
- a possible mitigation or patch, if available.

## Safe research boundaries

Only test systems you own or are explicitly authorized to assess. Do not disrupt services or access customer data. Public repository content never grants permission to test the author's infrastructure.

## Support and fixes

Fixes are assessed on a best-effort basis. No guaranteed response time or commercial SLA is implied by this policy. If a critical issue is under investigation, maintainers may coordinate disclosure timing before publicly sharing technical details.
